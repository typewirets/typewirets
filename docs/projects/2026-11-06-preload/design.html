Add container.preload() and a usePreload hook, fix useTypeWire's falsy check, and ship with #20 in 0.2.0

Key: preloadDate: 2026-11-06Author: Claude Code (Opus 5.5)Status: awaiting a pickServes: product.html B1–B11Source: core and react at a9dc4ac

Recommended: one new core method (container.preload(), every bound singleton, in parallel), one new React hook (usePreload, suspends a subtree once for a set of wires), a fix so useTypeWire returns falsy values, and docs. Named sets reuse the existing group.getAllInstances. B11 needs #20's fix, so this PR goes first and both ship together as 0.2.0.

What exists today

Fact (a9dc4ac)Matters for
F1. group.getAllInstances(ctx) resolves a group in parallel, imports included; its TSDoc already recommends it for preloading.B1: no new API needed
F2. container.getAllAsync() resolves every binding one at a time, transients included, and returns a Map. No test or doc uses it.B2: not fit as is
F3. useTypeWire ends with if (value) return value; throw promise;.B6: falsy values suspend
F4. ReactResolutionContext caches errors per symbol until clearErrors (#31).B3/B7: a failed preload rethrows, not re-suspends
F5. The react package's peer range is React 16.8+, but the provider renders <ContainerContext value>, which only React 19 supports.Hook must use the throw-a-promise pattern, like useTypeWire; F5 itself is out of scope
F6. Concurrent top-level resolves of a real cycle hang (issue #20, bug 2).B11

Recommendation

R1. A1 + H1 + S1, with the useTypeWire falsy fix and the docs. It meets B1–B10 with two small additions (one method, one hook) and no change to any interface that adapters implement. B11 comes with #20 before 0.2.0 ships.

Bounds, latitude and my calls

  • N1. No change to ResolutionContext or BindingContext; Inversify adapter users preload with groups (B1).
  • N2. Async contract unchanged: no change to apply, bind, getInstance, creators or overrides.
  • N3. Not now: transient wires in useTypeWire; useTypeWire calling getInstance every render; F5's React 19-only provider.
  • C1. My call: preload() returns Promise<void>; values are read with getInstanceSync, so it doesn't build a map nobody uses.
  • C2. My call: on failure, preload() rejects with the first failing creation's error (as Promise.all does) and still lets the other creations finish and cache.
  • C3. My call: usePreload accepts an array of wires or a group, and ignores transient wires in it.
  • L1. Builder decides alone: names, file layout, how useTypeWire tracks readiness. Checks first: any change to an existing public signature.

Risks

  • K1. Until #20 lands on main, a real cycle preloaded in parallel hangs. Mitigation: S1's release gate; changelog note if released alone is not an option.
  • K2. usePreload retry loops: if a preload fails, re-suspending forever is the trap. Rely on F4's error cache and test it (T7b). Timebox: half a day.
  • K3. StrictMode double render must not start a second creation; core's in-flight sharing (#28) covers it. Test it (T7).

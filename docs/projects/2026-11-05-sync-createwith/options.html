Make "sync" part of a wire's type, so the compiler proves the chain, rather than detecting it at run time

Key: sync-createwithDate: 2026-11-06Author: Claude Code (Opus 5.5)Status: awaiting a pick; replaces the A1 pick in design.html until decidedSource: two spikes on main a9dc4ac, TS 5.8.2

Runtime detection (A1) works, but it hides whether a wire is sync: a change three imports down silently turns a working sync read into a runtime error, and the types never say so. Making sync-ness part of the wire's type keeps the dependency chain type-safe. Recommended: O3, explicit sync wires that the compiler checks.

The four options

IDWhat a createWith wire doesWho decides it's sync
O0. Keep todayAlways async. Sync reads work only after a preload.Nobody: it's never sync on first use
O1. Runtime detection (was A1)Runs each import once; sync if none returned a promise.The run time, after the fact
O2. Inferred types + runtime detectionO1, plus typeWireOf returns a SyncTypeWire<T> type whenever the compiler can see the whole chain is sync.Compiler (visible) and run time (acts)
O3. Explicit sync wires, compiler-checkedA wire marked sync (e.g. sync: true) reads its imports synchronously, never awaits. The compiler rejects it if createWith returns a promise or any import isn't a sync wire. Unmarked wires stay as today.The author, checked by the compiler

Risks

RiskHitsMitigation
K4. Silent drift: a deep import turns async and a sync read breaks at runtime, in another moduleO1None in types; only tests that read sync.
K5. Creator contract change: a createWith creator returns a value, not a promise; .then on it in a withCreator decorator breaksO1, O2Changelog; Creator is already typed T | Promise<T>. O3: only for wires marked sync.
K6. Types lie (any, JS callers, a cast)O2, O3A marked-sync wire whose import turns out async throws AsyncOnlyBinding naming the import, instead of hanging or awaiting.
K7. Overload changes shift inferred types in user codeO2, O3SyncTypeWire<T> extends TypeWire<T>; typecheck the repo's tests and examples. O3 only adds overloads for the new option.
K8. Adoption: users must mark wires (and the sync leaves they import must be sync-typed)O3Leaves need no mark: a creator that returns a value is typed sync automatically (E5). Only createWith wires opt in.
K9. Cycle-path corruption from mixing sync and async readsO1, O2Build after #20's per-step chains.

Recommendation

  • R2. O3. It keeps your type-safe chain: sync-ness is something the author states and the compiler proves, so a deep change to async fails the build instead of a page at runtime. It changes nothing for unmarked wires, needs no runtime guessing and no #20, and behaves the same on the Inversify adapter.
  • Cost: the React fix is opt-in. A createWith wire suspends on first mount until its author marks it sync.
  • Later: O3 doesn't rule out O2. If marking feels heavy, inferring the sync type can come later on top of #20.

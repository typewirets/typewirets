A maintainer gets briefs agents can build from without asking again

Key: buildable-briefsDate: 2026-10-27Author: an agent, with the maintainerStatus: example product briefSource: the maintainer's answers in chat

Example product brief for the outcome-brief skill itself. The maintainer states what they want once, at a high level, and an agent turns it into a brief clear enough that a builder never has to come back to them.

Value

V0. A maintainer states what they want once, at the level of value, and gets a brief clear enough that an agent can build from it without coming back to them, whatever path the agent takes.

  • V1. Less rework: missing intent surfaces in the interview, not in review.
  • V2. Briefs age well: they state goals, so they don't go stale as agents improve.

Behaviour

IDBehaviour
B1Given a vague ask, the agent asks before building, and every decision comes with options, their evidence and a recommendation.
B2The product brief is one HTML page holding value and behaviour only.
B3Every behaviour line is something a test can observe.
B4Nothing is built before the product brief is approved.
B5The skill loads in Claude Code, Codex and Cursor from one copy.

Bounds, approaches and the agent's own calls are in the design brief.
